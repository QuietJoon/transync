**[CRITICAL] Per-unit cache keys omit output-affecting batch peers**

**Issue ID:** R0010-0001  
**Location:** `crates/transync-core/src/cache.rs:31-38`, `crates/transync-core/src/cache.rs:76-85`, `crates/transync-core/src/cache.rs:159-184`  
**Impact:** A unit can reuse an answer generated beside different peer source text, even though every peer appears in the same provider prompt and can influence the model's response.  
**Evidence / reasoning:** The key hashes the current unit, cohort/profile/context, and provider, but not the actual payloads of its co-batched units. Changing another unit while preserving packing can therefore leave this unit's key unchanged while changing its provider-visible request.  
**Recommendation:** Add a deterministic digest of the complete provider-visible batch envelope (or make caching batch-scoped), and version the cache contract.  
**Ignore/Decision reference:** No decision accepts reuse across semantically different provider prompts.

**[HIGH] Retry-conditioned answers populate the unconditioned cache key**

**Issue ID:** R0010-0002  
**Location:** `crates/transync-core/src/cache.rs:94-98`, `crates/transync-core/src/pipeline/dispatch.rs:375-450`  
**Impact:** A result produced only after a corrective retry hint can later be replayed as if it came from the original request.  
**Evidence / reasoning:** Retry context changes the provider prompt but is explicitly excluded from `CacheKey`; successful retry output is stored under that unchanged key.  
**Recommendation:** Include the effective retry instruction in identity, or only cache results whose provider-visible instruction is equivalent to a normal first attempt.  
**Ignore/Decision reference:** The retry side-channel decision keeps hints out of source content; it does not require excluding them from semantic cache identity.

**[HIGH] Explicit output paths may overwrite the source input**

**Issue ID:** R0010-0003  
**Location:** `crates/transync-cli/src/translate_cmd/output.rs:252-365`, `crates/transync-cli/src/translate_cmd/output.rs:562-618`  
**Impact:** `--force --output <input>` can replace the original document after it has been read, turning a translation command into destructive source mutation.  
**Evidence / reasoning:** Destination collision checks compare outputs with one another, but do not identity-check them against `--input`; publication later renames the staged file over the path.  
**Recommendation:** Add all read-side files to the preflight identity set and reject every input/output alias regardless of `--force`.  
**Ignore/Decision reference:** Output overwrite decisions cover existing destinations, not destruction of the run's source.

**[HIGH] Regeneration silently corrupts out-of-order or overlapping public block ranges**

**Issue ID:** R0010-0008

**Impact:** Programmatic callers can construct a public `Document` whose regeneration duplicates, drops, or reorders source bytes without an error.
