### 1. An unmarked directory containing a foreign file named html is treated as empty

**[HIGH] An unmarked directory containing a foreign file named html is treated as empty**

**Issue ID:** R0012-0001

**Location:** crates/transync-cli/src/output/preflight.rs:438

**Impact:** An ordinary --out-dir publication can delete unrelated data without --force.

**Evidence / reasoning:** The HTML_SUBDIR branch only inserts a published entry when html is a directory. A regular file or symlink named html is neither rejected nor recorded. **Ignore/Decision reference:** ADR-0029 permits ownership by marker name and complete-set recovery; this example has neither a marker nor a complete set. It is distinct from R0011-0003's accepted marker-body policy.

**Patch disposition:** A proposed diff is included; downstream review and validation remain necessary.

### 2. Case-insensitive leaf aliases bypass destination and input-overwrite checks

**[HIGH] Case-insensitive leaf aliases bypass destination and input-overwrite checks**

**Issue ID:** R0012-0002

**Location:** crates/transync-cli/src/output/destination.rs:125; crates/transync-cli/src/translate_cmd/publish.rs:155

**Impact:** On a case-insensitive volume, publication can overwrite the source/profile/prompt file despite the explicit read-side protection, or fail after a paid run when two outputs collide.

On a case-insensitive filesystem, --input source.md --output SOURCE.md addresses the same directory entry but the protected-read comparison sees different strings. Two outputs named result.json and RESULT.JSON similarly pass vet_destinations. This is a filesystem-dependent static finding; no filesystem mutation was used to reproduce it.

**Recommendation:** Compare directory-entry identities using the filesystem's name-equivalence rules while retaining the intentional distinction between a final symlink and its target. Cover existing read-side aliases and both existing/nonexistent output pairs on a case-insensitive test volume.

**Ignore/Decision reference:** R0010-0003 introduced read-side protection. The final-symlink exception documented in destination.rs does not justify treating two spellings of the same directory entry as distinct. No decision accepting case aliases was found.

**Patch disposition:** Needs a filesystem-aware entry identity design that preserves the accepted final-symlink behavior; a simple lowercase/canonicalize-everything patch would introduce false refusals.

### 4. Script double-escaped text makes the balancer remove a necessary closing tag

**[HIGH] Script double-escaped text makes the balancer remove a necessary closing tag**

**Issue ID:** R0012-0004

**Location:** crates/transync-html/src/lib.rs:903; crates/transync-html/src/lib.rs:2765

**Impact:** A valid raw HTML block can become an unterminated script region in a pane, consuming following sync anchors during parsing and causing mounting to fail or content to disappear.

**Recommendation:** Model script-data transitions separately from ordinary raw text, preferably consuming an authoritative tokenizer event stream. Add the complete fragment above followed by another anchor to the downstream browser oracle, asserting that the final script terminator survives and the following anchor remains a sibling.

**Ignore/Decision reference:** ADR-0018/DCR-0016 require pane balancing to protect following anchors. DCR-0050 expanded the raw-text set; it does not document accepting incorrect script-data termination.

**Patch disposition:** Needs a decision on extending script states versus adopting tokenizer events throughout the shared scanner; the raw-text/strip/balance consumers must remain coherent.

**Ignore/Decision reference:** DCR-0026 requires parent/window reporting. OI-0021 and R0001-0028 establish document ordering; they do not accept lexical order beyond the padding width.

**Patch disposition:** A proposed diff is included; downstream review and validation remain necessary.

### 25. Sequential prompt replacement reinterprets an inserted source label

**[LOW] Sequential prompt replacement reinterprets an inserted source label**

**Issue ID:** R0012-0025

**Location:** crates/transync-core/src/profile.rs:1363

**Impact:** An opaque source-language label containing a target placeholder is changed in the system prompt even though other request/cache fields retain the original label.

### 26. The coalescing contract incorrectly claims byte-identical complete requests

**[LOW] The coalescing contract incorrectly claims byte-identical complete requests**

**Issue ID:** R0012-0026

**Location:** docs/architecture/contracts.md:714

**Impact:** Readers are given a stronger reproducibility claim than the implementation or provider interface can support.

**Evidence / reasoning:** The paragraph says a coalesced batch's request is byte-identical to what its sections receive alone. Coalescing changes the units array and therefore the serialized user request. The invariants actually preserved are the compiled system prompt, instruction variant, and per-unit cache axes. DCR-0057 also uses overbroad request/output equivalence language; a live model can respond differently when peers change.

**Recommendation:** Limit the claim to the preserved prompt components and cache identity. Explicitly state that batch membership changes the full request and live output equivalence is not guaranteed.

**Ignore/Decision reference:** DCR-0057 authorizes coalescing and unchanged cache axes. This correction does not reopen the accepted decision to omit batch peers from per-unit keys.
