## 1. Context and problem

`transync` translates GFM Markdown documents and renders source/target side-by-side with block-ID scroll sync. Since ADR-0018 / DCR-0016 it also translates the *content* of raw-HTML blocks **inside** Markdown documents: the `htmlseg` engine (`lol_html`) extracts text segments, the model sees only text, and splice-back preserves markup by construction. What it cannot do is take an **HTML document** as input. The CLI's preamble sniff refuses `<!doctype`/`<html`-shaped input with a pointer at this ticket; `html_dominance_warning` names "HTML-to-HTML translation is not implemented (ti 490d97)" as the library-side backstop.

This design makes an HTML document a first-class input: parsed by a new HTML intake into the same block IR, translated by the same pipeline through the same segment engine, regenerated byte-preserving outside translated text, validated by a format-appropriate layer-6 gate, aligned, and mounted in syncing panes — **one pipeline, two intakes**, never a parallel HTML pipeline.

The shape of the problem, and why the design looks the way it does:

- The shipped IR conflates *semantic kind* with *source spelling*: `BlockKind::Html { block_type: u8 }` means both "no semantic classification" and "spelled as HTML". An HTML document's `<h1>` is semantically a heading; calling it `Html` would forfeit section partitioning, heading context, and honest wire labels. Decision 2 splits the axes.
- The HTML mechanics (`htmlseg`) already live in `transync-syntax` as a `#[doc(hidden)]` module. The intake, the layer-6 twin, and the pane injector all need its scanner and discipline; keeping it hidden inside one crate would force either re-implementation (a second HTML opinion — forbidden by the same rule that forbids a second Markdown parser) or an awkward visibility widening. Decision 3 extracts it.
- Everything downstream of the IR — batching, prompting, caching, retry/fallback, alignment, the sync engine — is already format-agnostic or one dispatch away from it. The verification pass confirmed this repeatedly: `regen::regenerate` copies gaps and tails verbatim and is format-blind; the retry cascade consumes only `ReparseFailure { reason, divergent_source_blocks }`; `CacheKey` already carries `input_mode`. The feature is large but the architecture does not move.

**Correction the spec must carry (the ticket is stale):** the ticket's *API impact* section names `translated_markdown → translated_document` as "the only genuine v0.4.0 coupling". That rename **already landed in v0.4.0 under this ticket's own number** — contracts.md §0 records it against ti 490d97 and the field is `translated_document` throughout the tree. Nothing of that item remains open. The ticket's "API impact: lands additively" claim is likewise superseded: decision 2's four IR changes are breaking-by-policy and ride the v0.5.0 window (decision 12).

## 2. The twelve decisions

Each entry records the decision, its rationale, and what it rejected. These are settled; the spec never re-argues them.

**D1 — Scope: one spec, staged waves.** The whole feature is designed here; implementation is staged into the eight waves of §12, each with a demonstrable outcome. Rejected: per-area partial specs (the synthesis showed the areas' seams — the splice policy, the pane list-grouping, the twin's segmentation projection — are exactly where independent designs diverged; one document is the anti-drift instrument).

**D2 — Semantic kind ⊥ spelling.** `BlockKind` stays the semantic vocabulary; a new per-block `Spelling` says how the source spelled the block; `BlockKind::Html` narrows to "HTML content with no semantic equivalent" (a `div`, a custom element). An HTML `<h1>` is `Heading1` + `Spelling::Html`; a Markdown island stays kind `Html` + `Spelling::Html { Some(block_type) }`. Rejected: *deriving* spelling from `document format × kind` (true today, but it hard-codes the very conflation the decision removes and collapses when D11's deferral ends); keeping `block_type` on the kind (it is 100 % spelling metadata — its only consumers are splice normalization and `HtmlSegmentConstraints`).

**D3 — Crates: layer axis, not format axis.** The HTML mechanics move to a new crate (named by D10); the workspace keeps its layer-based crate axis; the *format* seam is a module boundary inside `transync-syntax` — `intake::markdown` (today's `parser`) beside `intake::html`. Rejected: a format-axis crate split (`transync-markdown` / `transync-html-format`) — intake classification names `BlockKind`/`Block`, so a format crate would either depend on the IR (inverting the layer axis) or duplicate it.

**D4 — Block definition: structural pass-through, content stop, unknown stop.** Structural/grouping elements (`div`, `section`, `body`, …) pass through — their markup becomes inter-block gap bytes that `regen` copies verbatim. Segmentation stops at content elements (`h1`–`h6`, `p`, `table`, `pre`, `blockquote`, `li` per D9, …), which become leaf blocks of the matching semantic kind. Unknown and custom elements **stop** as `BlockKind::Html` — the safe direction: over-stopping yields a coarser block; under-stopping would leak text into untranslated gap. Rejected: top-level-`<body>`-children as blocks (a wrapper-heavy page would become one giant block); budget-driven block sets / intake descent into oversize elements (block identity would depend on token budgets). Two recorded amendments to the decision's literal element list: the PHRASING class (§4, a necessary widening — without it `Hello <b>world</b>` shatters into three blocks; its consequence is a named post-implementation review item, §14) and D9's list ruling.

**D5 — Head policy: `<title>` translated, anchor-less; attribute text untranslated.** The `<title>` is real translatable content and gets a real block, a real unit, and a real alignment row — but no DOM anchor: it is rendered by browser chrome, not the pane. Its row ships `sync_role: "non-sync"`, the shape a thematic break has had since schema 1.0. **This amends architectural invariant 1** (wording in §10). Attribute text (`alt`, `title`, `placeholder`, `<meta description>`, `og:*`) stays untranslated — an explicitly accepted limitation (§13) with its visible consequence named: *a shared link previews in the source language.* Rejected: skipping the head entirely (the title is the single highest-value string on many pages); anchoring the title (there is nothing in the pane to anchor).

**D6 — Panes are a sync surface, not a fidelity preview.** The bundle's panes exist to sync blocks, exactly as they do for Markdown. Viewing the real translated page — head, scripts, styles, layout — is `transync serve` over the published `out.html`. Rejected: panes-as-fidelity-preview / whole-document annotated panes (§8 gives the four-point argument: it breaks contracts §4a's direct-child invariant, corrupts `offsetTop` geometry via source-controlled `style` attributes, re-opens OI-0035's attack surface, and provides exactly the thing D6 declines to provide).

**D7 — Entity drift accepted.** Translated segments lose named-entity spelling (`&nbsp;` → U+00A0, `&copy;` → ©); untouched segments and identity-skipped echoes keep their source bytes exactly. Accepted and already test-pinned since DCR-0016; this feature adds population, not policy. Records-only.

**D8 — CLI: explicit `--input-format markdown|html`; the sniff stays a refusal, never a router.** Routing is flag-only; the operator asserts the format. The preamble sniff continues to refuse HTML-shaped input on Markdown runs (with an updated pointer message) and is not consulted on HTML runs. Rejected: sniff-as-router (content sniffing was put out of scope by ti 13e145; silent format selection is exactly the class of guess ADR-0017's refusals exist to prevent); a reverse sniff on HTML runs (a body fragment is legitimately accepted HTML and no preamble check can recognize one). **Confirmed final ruling on the decision's open half:** `--allow-html-input` is **kept**, narrowed in documentation only to its real case — "this is Markdown that opens with an HTML island" — plus a new **exit-1** argument-conflict rule against `--input-format html` (§9).

**D9 — `<li>` is the block, not `<ul>`.** The owner ratified the synthesis's recommendation; **this deviates from decision 4's literal element list** (`ul`/`ol` appeared among the stop elements) and the deviation is recorded here. Rationale: (a) one block-granularity convention across both intakes — the shipped Markdown model is leaf `ListItem` blocks, and `align::sync_role_for`'s comment, `render::render_list_group`, `wrapper_element_for(ListItem) => "li"`, and `walk::normalize_top_level`'s prefix collapse all already assume item-level anchors; (b) per-item fallback instead of whole-list fallback; (c) it dissolves the oversize-list problem without the intake descent D4 rejected — a 400-item list is 400 units, not one 200 KB unit needing a splitter that does not exist. Cost, accepted: `<ul>`'s own tags become gap bytes (which `regen` preserves verbatim — verified), and there is one anchor per item rather than per list. Rejected: `<ul>` as one block (the validation area's twin projection was written against it; that projection is rewritten to this ruling — §7).

**D10 — Crate name: `transync-html`.** The owner chose this over the synthesis's recommendation `transync-htmlseg`, on the reasoning that "segment" now under-describes a crate that also owns tokenization (`scan_tags`), the pairing discipline, and element extents — and over-description ages better than under-description. Also rejected: `transync-html-core` (the owner's own working name — `-core` already means "the pipeline" in this workspace, so the name would claim pipeline status for a mechanics crate); `transync-lolhtml` / `transync-rewriter` (name the dependency or the implementation, not the capability). **Required consequence:** the crate's doc comment must state that structural intake — classification, `BlockKind` assignment, ids — lives in `transync-syntax::intake::html`, *not* here; `transync-html` is the mechanics layer under it. This note is what keeps the natural-looking-but-wrong reading of the name from misleading a contributor.

**D11 — Markdown-island reclassification is deferred.** All four design areas independently reached the same answer, and the owner ratified it: the Markdown intake keeps emitting `BlockKind::Html` for raw-HTML islands; D2's narrowed meaning ("no semantic equivalent") binds the **HTML intake** only. Reclassifying an island (`html-0007` → `t-0007`) moves block ids — verified: id prefixes come from `id_code()` — and with them alignment rows, DOM anchors, and the `block_kind` cache axis, violating the acceptance criterion *"the Markdown path stays byte-identical over the existing corpus"*. Deferred to a future schema-2.x-shaped window, recorded in ADR-0025. Defensible on its own terms, too: a `<table>` island has a semantic equivalent only if someone parses it, which the Markdown intake deliberately does not.

**D12 — Version: v0.5.0.** The four breaking-by-policy changes (`Block.spelling`, `Document.format`, `BlockKind::Html` narrowing, `BlockKind::Title`) ride one sanctioned v0.5.0 window. The owner considered v0.4.1 with the measured facts in hand — neither known consumer breaks (`dynwebserver` has `_ =>` wildcard arms and never constructs `Block`; `resp-translator` never names `BlockKind`; nothing is published to crates.io yet) — and **chose v0.5.0 anyway**: a policy exception is more expensive later than a version number is now, and `CodeBlock.fenced` rode a sanctioned window four days earlier for a strictly smaller change. Rejected: v0.4.1 (would establish that breaking-by-policy changes can ride patch releases when no consumer is measured to break — a precedent that erodes the policy exactly when it matters).

**Three final confirmations** recorded with the decisions: (i) `--allow-html-input` kept/narrowed + the exit-1 conflict (folded into D8 above); (ii) **neighbor snippets stay verbatim source excerpts for both formats** — only heading context and `document_title` project through `extract` (§6; keeps the pinned test `neighbor_summaries_stay_verbatim_source` green); (iii) the PHRASING widening's consequence is **accepted for now** and is a named post-implementation review item, not a settled matter (§14).

## 3. Data model and IR

Two new types in `transync-syntax::id`, beside `BlockKind`, because they are the same class of thing — projection-bearing vocabularies that move in lockstep with their consumers:

```rust
/// How the source spelled a block. The semantic vocabulary stays on
/// `BlockKind`; this axis is orthogonal (D2, ti 490d97).
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub enum Spelling {
    /// GFM syntax. Every consumer that reparses under comrak lives here.
    Markdown,
    /// Raw HTML markup, translated via segment extraction/splice.
    Html {
        /// CommonMark HTML block type (1–7) when the block is an island
        /// inside a *Markdown* document. `None` for every block of an
        /// *HTML* document, where no CommonMark context exists and
        /// blank-line collapse must never run.
        block_type: Option<u8>,
    },
}

/// The plain two-value format label: `Document.format`, per-row
/// `source_format` on the alignment wire, `AlignmentMap.input_format`,
/// and the `TranslateOptions` input-format option.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize)]
#[serde(rename_all = "kebab-case")]
pub enum SourceFormat { Markdown, Html }
```

- **`Block` gains `pub spelling: Spelling`; `Document` gains `pub format: SourceFormat`.** Per-block is required, not stylistic: the Markdown parser's `NodeValue::HtmlBlock` arm interleaves Html-spelled blocks with Markdown-spelled ones inside one document, so a document-level bit cannot carry the axis. `Document.format` does a different job — it lets format-committed consumers (`validate::full_reparse`, the Markdown renderer, comrak-based context) *refuse* the wrong document instead of silently producing garbage. Invariant: `format == Html` ⟹ every block's spelling is `Html { block_type: None }`; `format == Markdown` ⟹ spellings are mixed, Html islands carry `Some(t)`.
- **`BlockKind::Html { block_type: u8 }` narrows to a unit variant `BlockKind::Html`** — "HTML content with no semantic equivalent" — and `block_type` moves to `Spelling::Html`. Its only consumers are spelling machinery (splice normalization; `HtmlSegmentConstraints`), verified by grep in the design session. Wire impact: none — no shipped artifact serializes the enum form (verified via the `fenced` doc comment's enumeration: alignment rows and `CacheKey` carry `wire_str()` strings; `TranslationUnit` is not `Serialize`).
- **`BlockKind::Title` is added** for D5: `id_code() = "title"` (no collision in the existing prefix set), `wire_str() = "title"`, `heading_level() = None`, `is_translatable(Title) = true`. **Two shipped catch-alls will not warn the implementer, and the arms must be explicit** (a verification-pass correction to the design's own first draft): `align::sync_role_for` ends `_ => SyncRole::Anchor` — without an explicit `Title => SyncRole::NonSync` arm plus a test, the new variant silently becomes an *anchoring* row, the precise opposite of D5; and `unit::context::document_title` matches `BlockKind::Heading1` **only** (not "any heading", as one area report asserted — verified), so `Title` does not enter the document title for free and `document_title` is explicitly extended to prefer a `Title` block. The matches the compiler *will* walk you to: `id_code`, `wire_str`, `walk::label_for`, `per_kind::check`, `render::wrapper_element_for`, `input_mode_for`.
- **All four changes are breaking-by-policy** (contracts §1 for the enum; all-`pub`-field non-`#[non_exhaustive]` structs for the two fields — verified) and ride the one v0.5.0 window (D12), batched, recorded the way `CodeBlock.fenced` was: contracts §0 prose paragraph, §1 stability bullet, CHANGELOG BREAKING entry.
- **Deferred and recorded:** Markdown-island reclassification (D11).

Wire form (schema 1.3.0, both additive — `AlignmentMap` and `AlignmentBlock` are `#[non_exhaustive]`, verified):

- **Row-level `source_format`: `"markdown" | "html"`** — the block's spelling. Mandatory in 1.3.0 output (the acceptance criterion says *rows for every block with `source_format` declared*). The Rust field is `Option<SourceFormat>` solely so `Deserialize` accepts a pre-1.3.0 map; the documented reader rule for an absent value: **`block_kind == "html" ? html : markdown`** — a bare "default markdown" is rejected because it would mislabel every 1.2.0 html-island row.
- **Map-level `input_format`: `"markdown" | "html"`** — the run's intake, which is what a pane mounter branches on. Two different facts, two distinct names; the synthesis found two areas colliding on one name here, and the ruling is both fields, never one doing double duty.

## 4. HTML intake and segmentation

Module `transync-syntax::intake::html`, sibling to `intake::markdown` (today's `parser`, renamed as part of the seam — path details are the implementation plan's, not this spec's). Input is `source_text` after the same `normalize_source` (NUL → U+FFFD) so both intakes mean the same string by "source bytes"; the HTML tokenizer state machine's own NUL convention agrees.

**Classification table** — five classes, default STOP:

- **PASS-THROUGH** (markup → gap bytes): `html`, `body`, `div`, `section`, `article`, `main`, `nav`, `aside`, `header`, `footer`, `hgroup`, `figure`, `details`, `form`, `fieldset`, `search`, `center`; `head` in head mode; and — per D9 — `ul`, `ol`, `menu`, `dl` pass through **to their items**.
- **STOP → semantic kind**: `h1`–`h6` → `Heading1..6` (opening/closing `SectionStack` scopes exactly as Markdown headings do — which is what makes `partition_by_section`, whose predicate is `heading_level().is_some()` (verified), work unchanged); `p`, `figcaption` → `Paragraph`; `table` → `Table` (whole element, one leaf block — invariant 3's posture); `li` (direct child of `ul`/`ol`/`menu`) → `ListItem { ordered: parent == ol, task: None }` (leaf — a nested `<ul>` stays inside the item's range, mirroring the Markdown leaf-item model); `pre` → `CodeBlock { info: None, fenced: true }` (`fenced` is **vacuous under Html spelling** — both consumers of `fenced == false` sit behind `Spelling::Markdown` dispatch after the split; the field doc gains that sentence); `blockquote` → `Blockquote`; `hr` → `ThematicBreak`; a textless run whose only non-whitespace content is **one or more** `img` elements → **one** `Image` block (see rule T, which owns this case; the one-or-more form mirrors Markdown, where `classify::paragraph_kind` promotes an image-only *paragraph* — however many images it holds — to a single `BlockKind::Image`); `title` in head mode → `Title`.
- **VERBATIM** (never a block; bytes stay gap): `script`, `style`, `link`, `meta`, `base`, and everything in head mode except `title`. Extraction already excludes script/style text by `TextType`; these have no reader-visible anchor surface, and a `PreservedZeroSegment` row per `<script>` would flood the map with anchor-less rows.
- **PHRASING** (absorbed into text runs, never a boundary): the standard inline set — `a`, `abbr`, `audio`, `b`, `bdi`, `bdo`, `br`, `button`, `canvas`, `cite`, `code`, `data`, `del`, `dfn`, `em`, `embed`, `i`, `img`, `input`, `ins`, `kbd`, `label`, `mark`, `math`, `object`, `optgroup`, `option`, `output`, `picture`, `q`, `rp`, `rt`, `ruby`, `s`, `samp`, `select`, `small`, `span`, `strong`, `sub`, `sup`, `svg`, `textarea`, `time`, `u`, `var`, `video`, `wbr`. This class is a **recorded widening of D4**, and it is load-bearing: without it `Hello <b>world</b> out there` at `div` level shatters into three blocks and the sentence crosses translation units. A phrasing element's text is not lost — rule T wraps the run into one `Paragraph` and `extract` descends into it. **Recorded consequence, accepted for now (§14):** a *custom* element mid-sentence still stops (D4 verbatim), so `Price: <my-price/> today` splits into three blocks — loud rather than silent, per D4's own rationale, but visible in output.
- **DEFAULT-STOP** → `BlockKind::Html`: `summary`, `dt`, `dd`, `address`, `dialog`, `iframe`, `noscript`, `template`, `legend`, custom elements, future elements. `<template>` needs no special case — it stops, extracts zero segments, lands `PreservedZeroSegment`.

**Algorithm.** One stack walk over `element_extents()` + the token stream (both published by `transync-html`, §5), under the crate's single pairing discipline — `implicitly_closes`, `is_void`, self-closing-honoured-only-in-foreign-content, raw-text suppression (all verified present under today's `balance_fragment`; the third was **self-closing-non-raw-text-counts-as-closed** when this spec was written and was **corrected 2026-08-23**, ti `490d97` wave 1 — a browser ignores the flag on a non-void, non-foreign element, so such a tag opens and its author's end tag is a real closer rather than an orphan to delete). A STOP element pushes a **leaf root**; nothing is emitted inside one (identical to the Markdown walker never recursing past a top-level node). Implicit closes (an open `<p>` pops when `implicitly_closes` says so), force-closes on unclosed leaves (`<div><p>text</div>`), and EOF force-close each append a `Document::warnings` note — that channel is documented as not parse-only.

**Rule T (anonymous text runs):** at pass-through level (never in head mode), a maximal run of [text bytes + PHRASING elements + `Skip` spans] bounded by hard boundaries (non-phrasing open, enclosing close, EOF) that contains at least one non-whitespace byte **outside** tag and `Skip` spans (U+FEFF stripped before the test — a leading BOM must not mint a paragraph) becomes one `Paragraph`, `Spelling::Html { block_type: None }`, range trimmed of leading/trailing whitespace + `Skip` spans + BOM. A textless run is gap — nothing translatable exists, nothing is lost, bytes preserved verbatim. **Exception:** a textless run whose only non-whitespace content is one or more `img` elements becomes **one** `Image` block, so images keep a sync anchor instead of dissolving into gap. Two adjacent `<img>` tags are therefore one `Image` block, not two and not gap — the Markdown side behaves the same way, and §11 pins the two-image case because an earlier draft of this spec stated the rule two ways. RCData counts as text (a bare `<textarea>` has translatable content); script content cannot reach a run because `script` is VERBATIM and a hard boundary. The `Skip` token exists in part for this rule — **MEASURED: `<!DOCTYPE html>` produces no token *and no skip* in today's scanner** (the `!` fails the ascii-alphabetic first-byte test, so the bytes are ordinary text to it), and without `Skip` a doctype-only gap would mint a phantom paragraph.

**Ranges = the whole element, tags included** (void elements = the tag span; anonymous runs = the trimmed run; forced closes = up to the boundary token, trailing whitespace excluded). Justified against each named consumer: `outcome::block_payload` feeds the slice to `extract`, which wants markup and yields real parent labels (prompt-visible `segment_labels`); `HtmlSegmentConstraints.source_bytes` is the splice-check input, so whole-element makes the layer-3 ledger cover the element's own tags — strictly stronger than content-only; `regen`'s fallback arm splices `source_text[bstart..bend]` verbatim, so fallback reproduces the element exactly (invariant 6); `source_hash` then covers attributes, so `<p class="a">x</p>` and `<p>x</p>` cannot alias in the cache.

**Ids, hashes, paths.** Emission-order stamping with the same global-ordinal scheme (`BlockId::new(kind.id_code(), counter)`, one counter for all kinds — verified); the pipeline's existing `assign_block_ids` is idempotent over it and remaps `section_path`. `document_id` stays `source_hash_bytes(source_text)`. `ast_path` mirrors comrak's child-index convention — an `<li>` takes its list container's path + item ordinal, exactly the Markdown List-arm convention, so `walk::normalize_top_level`'s prefix collapse stays total and adjacent lists can never merge. No line table is involved anywhere (spans are direct byte offsets), so the lone-CR/NUL sourcepos hazards (OI-0033/0034) structurally cannot recur on this path.

**Regen's three requirements are provable at intake:** source order (emission follows token order behind a monotone cursor; a leaf fully pops before pass-through level resumes, so no block starts inside another); non-overlap (corollary); every offset a `scan_tags` byte offset into `source_text`, with span endpoints on ASCII `<`/`>` and trims across ASCII whitespace — so every boundary is a UTF-8 char boundary and `block_payload`'s defensive snap is the identity, exactly as for comrak ranges. A debug assertion pins order/non-overlap at intake; the layer-6 twin re-verifies boundaries at the far end (§7).

**`<title>`:** emitted in source order (typically `blocks[0]`), `section_path` empty (it opens no scope; `partition_by_section` puts it in the preamble section — correct, since no glossary section-selector can mean a page title). Alignment row: `block_kind: "title"`, `source_format: "html"`, real ranges, real `fallback_status`, `sync_role: "non-sync"`. Its unit is an ordinary `HtmlSegments` unit with one RCData segment labelled `title` (extraction of `<title>` is measured/shipped behavior). Head mode: only `title` stops inside `<head>`; a duplicate title yields two honest rows; a `<title>` outside head mode (or `<svg><title>`, a different element inside a stopped leaf) is never `Title`.

## 5. The `transync-html` crate

**What moves:** `htmlseg.rs` moves verbatim (file-as-module split allowed later); `transync-syntax` loses `#[doc(hidden)] pub mod htmlseg` with **no re-export alias** — a hidden alias would be the "misleadingly-named thin wrapper" D3 rejects, and contracts §0 grants the engine tier a weaker stability promise (nothing is published to a registry yet). Complete external caller inventory, from grep (all hits): `outcome::…` (`extract`), `regen::…` (`splice`), `render::…` (`balance_fragment`), `unit/payload::…` (`extract`), `validate::…` (`splice`, `tag_inventory`).

**Crate-doc note (required by D10):** the crate documents itself as the HTML *mechanics* layer — tokenization, pairing discipline, element extents, segment extract/splice, fragment balancing — and states explicitly that structural intake (classification, `BlockKind` assignment, ids, `ast_path`) lives in `transync-syntax::intake::html`, not here.

**Public API:**

```rust
// ── segment engine ──
pub struct HtmlSegments { pub texts: Vec<String>, pub labels: Vec<String> }
pub fn extract(block: &str) -> Result<HtmlSegments, String>;
pub fn splice(block: &str, translated: &[String], blank_lines: BlankLinePolicy)
    -> Result<String, String>;

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum BlankLinePolicy {
    /// Interior blank lines in a translated segment are collapsed — the
    /// Markdown-host rule: a blank line terminates a CommonMark HTML block
    /// of type 6/7 at reparse, splitting the block and breaking anchors.
    Collapse,
    /// Blank lines pass through. Correct for CommonMark types 1–5 and for
    /// every block of an HTML document (nothing ever Markdown-reparses it).
    Keep,
}
impl BlankLinePolicy {
    /// The one home of the CommonMark mapping: 6|7 → Collapse, else Keep —
```

## 6. Units, prompt and cache

**The unit-level carrier of spelling is `InputMode::HtmlSegments`** — already the payload-semantics axis, already a prompt label, already a `CacheKey` axis. Documented invariant, established at `unit::payload::assemble` and never re-derived elsewhere: *spelling Html ⇔ `InputMode::HtmlSegments`*. No new `TranslationUnit` field (it is `#[non_exhaustive]`, so one could be added — but it would duplicate what `input_mode` states).

The structural insight the whole pipeline area rests on: **for an HTML-spelled unit, structure never crosses the wire.** `assemble` sends `serde_json::to_string(&segs.texts)` — a JSON array of decoded text segments; markup stays in `HtmlSegmentConstraints.source_bytes`, documented "never sent to the model". The model physically cannot change a column count, heading level, or list topology it never sees; the enforcement point is layer 3's splice + ordered tag ledger, which already proves the output block's tag skeleton equals the source's exactly. Tag-sequence identity **subsumes** column-count identity — so per-kind structural validation for (any kind × Html) is vacuously satisfied *by construction*, and this rationale is written into `per_kind`'s module doc rather than left implicit.

- **`assemble` branches on spelling first** (not kind) — which structurally prevents `(CodeBlock × Html)` from ever reaching `code_payload`'s indented-block re-fencing: DCR-0031's fence synthesizer is Markdown-only, and the branch order is what makes that a compile-shape guarantee rather than a convention.
- **`constraints.html` carries the same four fields** (`segment_count`, `segment_labels`, `source_bytes`, `block_type`); for HTML-document units `block_type = 0`. `HtmlSegmentConstraints` is a §0 tier-(a) row without `#[non_exhaustive]` (verified), and the v0.4.0 window closed on release — the field's type is frozen, so `Option<u8>` was off the table. The synthesis merged three competing proposals into: `BlankLinePolicy` wins the crate-side naming; **`0` wins the sentinel** (over a proposed `1` — behaviorally identical since `matches!(t, 6|7)` treats both the same, but `0` is honest: the amended doc comment reads *1–7 = the CommonMark block type of an island inside a Markdown document; 0 = a block of an HTML document, where no CommonMark type applies*; doc edits are not breaking); and **the splice policy is derived from the unit's spelling **at regen**, and re-derived at **validation layer 3** from the recorded type through the one constructor, pinned equal** — the field is a record, and reading it is not a second opinion. *(Corrected 2026-08-24 by design review. This read "always derived from the unit's spelling, never from the constraints field", which is false at layer 3 and **structurally cannot** be true there: `TranslationUnit` carries no spelling and `InputMode::HtmlSegments` carries no `block_type`, so `constraints.html.block_type` is layer 3's only home for the CommonMark type. The two answers agree through `0 → Keep ≡ None → Keep`, which wave 2 Task 2's test pins explicitly — that equivalence is the weld and must never be weakened. Wave 5 then gives the sentinel a **second** sanctioned read: `DocumentFacts.html_document` is derived from `block_type == 0` because `TranslationBatch` is a §0 tier-(a) **exhaustive** struct and a fifth breaking change was not taken; that derivation has a single site, a `debug_assert` against `doc.format`, and an island-never-raises-it pin. So "record, not a switch" governs the **splice policy**; it does not forbid the two pinned re-derivations.)* No Markdown structural constraints (`must_preserve_table_columns` etc.) are set for HTML units: they are prompt-visible hints about structure the model cannot touch, and the ledger is stronger.
- **Context projection:** `heading_plain_text` runs comrak over the range slice (verified), so an HTML `<h1>` would put raw tags into the heading stacks and `context_hash`. For Html-spelled headings the plain text becomes `extract(payload).texts.join(" ")`, trimmed — the one existing HTML opinion, entity-decoded, spelled exactly as the model sees the wire segments (the DCR-0027 property). This lands in `build_index`'s `headings` map (it calls `heading_plain_text` per heading — verified), not only at the call site. `document_title` prefers the first `Title` block's extracted text for an HTML run, falling back to the first heading. **Neighbor snippets stay verbatim source excerpts for both formats** (final confirmation ii): `neighbor()` uses `text_from_range_truncated`, and the pinned test `neighbor_summaries_stay_verbatim_source` documents the deliberate contrast — a Markdown neighbor summary is already raw source (`| a | b |` markup), markup in an HTML excerpt is honest on the same terms, and the smaller change keeps a shipped pin green. Rejected: the IR area's proposal to project neighbor summaries through `extract` (it would break the pin for a prompt-nicety).
- **Prompt:** additive profile key **`[system].prompt_html`** — a sibling template body, shipped in the default profile, selected at cohort-compile time for an HTML-format run. A custom profile without one falls back to `prompt` unchanged **plus a load warning** ("profile has no [system].prompt_html; its system prompt was written for Markdown") — advisory, never a core-synthesized merge into operator-owned text. `InstructionVariant` gains `html_document: bool`, set run-level from the input format (known before packing; no circularity with `DocumentFacts`); its clause ≈ "These units come from an HTML document. Segment text is HTML text content — never introduce Markdown syntax into a segment." The existing html-segments clause rides anyway via the re-keyed `has_html_unit` (§7). Markdown runs assemble byte-identical prompts and instructions — the goldens that pin them stay green.
- **Cache: no new axis.** The owner's own rule (contracts §5a): if it changed the prompt bytes the model saw, it is identity; if not, it is not. ## 7. Validation, including the layer-6 twin

**Re-keying (behavior-preserving on the Markdown path, since kind-Html ⇔ mode-HtmlSegments holds today; each site pinned by existing tests, so this can land before any intake exists):** `fragment_reparse`'s early return; `schema::check_payload_bytes`'s JSON-decoded NUL scan; `inline::check_inline`'s skip set; `per_kind::check`'s new first arm — `InputMode::HtmlSegments` → `check_html` for **every** kind, with the §6 by-construction rationale in the module doc (an HTML `<table>` does have a column count; checking it here would be strictly weaker than the per-unit ledger, which is why `check_table` gets no Html variant — honest early-return, not inability); layer 3's splice check keyed on `constraints.html` presence with the mode as debug-assert twin, policy derived from spelling; `llm/prompt::has_html_unit`; `outcome::is_translatable_block` / `html_outcomes` iterate spelling-Html blocks (the kind-level exclusions — ThematicBreak/Image/Skipped — become the Markdown arm; the per-block `HtmlOutcome` mechanism generalizes verbatim, `PreservedZeroSegment` included); the `build_batches` outcome-map skip; and an explicit, tested guard excluding `(Table × Html)` from `unit::split::split_oversize_tables` (`inspect_table` would return None on HTML anyway; the exclusion must still be explicit). `pipeline::merge` is untouched — no HTML row windows exist.

`id_code` / `wire_str` / `heading_level` take **no** HTML arm — semantic kind wins, so an HTML `<h1>` is `h1-0001` and `partition_by_section` works for free. `walk::*` takes no HTML arm either: it is the *Markdown* layer-6/renderer pairing and must simply never be called on an HTML document — enforced by the format branch in `finalize`, not by adding arms.

**The layer-6 twin — `validate::full_rescan_html(source_doc, regenerated, offsets) -> Result<(), ReparseFailure>`.** Same scanner the splice used; four checks, in order:

1. **Document-wide ordered tag ledger** — `tag_inventory(regenerated) == tag_inventory(source_text)`. The ledger is an ordered `Vec`, so this catches dropped/duplicated/reordered markup anywhere — inside blocks and in gap bytes alike (pass-through wrappers live in gaps, and the ledger still tokenizes them).
2. **Fresh segmentation** — re-run the intake segmenter over the regenerated document; compare block count and kind-label sequence against `doc.blocks` in order. Written to **D9's ruling** (per-`<li>` blocks — the validation area's original projection assumed whole-`<ul>` blocks and is superseded). Divergence attribution mirrors `attribute_offenders`: map each fresh block's start offset into the `BlockOffsets` ranges; a source block owning ≠ 1 fresh block is the offender.
3. **Gap byte-identity** — memcmp consecutive target-range gaps (plus preamble and tail) against the source's. This is the check with no Markdown twin, and it exists precisely to close the ledger's two **MEASURED** blind spots: `<!DOCTYPE>` and comments produce no token in `scan_tags`, so a dropped doctype or comment is ledger-invisible — but it is a gap byte, and gaps must be verbatim. In HTML, gaps carry meaning (head, scripts, structural wrappers); the twin re-reads them from the *output*, which is the whole point of a layer-6 gate.
4. **Boundary sanity** — offsets monotone, non-overlapping, in-bounds against the actual output length: cheap re-verification of regen's bookkeeping.

**Honestly recorded residuals:**

- **Two same-kind, identical-tag-skeleton blocks whose texts were swapped by an engine fault pass all four checks.** This is exact parity with the shipped `reparse_full`'s blindness to two swapped paragraphs — parity, not regression. Per-unit layer 3 already ledger-checks each accepted splice individually, which bounds the fault surface to regen's assembly ordering; checks 3 + 4 jointly cover any block whose neighbors differ.
- **Attribute values are not tokenized** (`scan_tags` skips attribute internals; RCDATA/raw-text contents are never tokenized). Compensating controls: splice never edits inside tags by construction, translated-text escaping is pinned by test, and the fixture acceptance criterion ("untouched markup byte-identical outside text nodes") tests it end-to-end.
- **`scan_tags` is not a general HTML parser** — fine, because both sides of every comparison use the *same* scanner: the check is self-consistency of one tokenizer opinion, the same rule the architecture enforces for comrak.

**Cascade:** `finalize_regen_with_reparse_policy` gains **one** format branch on `Document.format` — `reparse_full` for Markdown, `full_rescan_html` for HTML. `ReparseFailure`'s shape is unchanged, so `downgrade_units` / `widen_to_neighbors` / `fall_back_all` are untouched (verified: they consume only `reason` + `divergent_source_blocks`, and `widen_to_neighbors` runs over `top_level_blocks` = `blocks.iter()`).

**Retry and fallback — invariant 6 survives, mechanically:** `check_html` rejections are retryable layer-2 failures; `retry_validation_unit` re-attaches only the non-content `RetryContext` — resubmission stays verbatim per ADR-0009; nothing HTML-specific enters this path. Exhaustion, or a layer-3 engine fault via `direct_fallback` (`rejected_by: None`, no retry — correctly), sets `FallbackStatus::FallbackSource` with `accepted_payload: None`; `regen_pass` filters to `Some` payloads, so `regen` splices the fallen block's source bytes **byte-verbatim** — the only payload rewriter (`code_payload`'s re-fencing) is unreachable for HTML-spelled blocks by §6's branch order. Per block, never per document; every cascade arm ends `Ok`, never corrupt output.

**Hard rule (also stated at wave 4 in §12): no HTML translation run ships before the twin exists.** comrak over an HTML document produces *some* node sequence and can pass while checking nothing — an HTML run gated by `reparse_full` is worse than ungated.

## 8. Render, anchors and OI-0035

**Panes are synthesized `<main>` fragments**, not annotated whole documents. Four reasons, all tracing to locked decisions: (1) D6 — the whole-document form's only advantage is fidelity, the thing D6 declines to provide; the fidelity door is `transync serve`. (2) Contracts §4a — "a single `<main>`, every block a direct child, in source order" keeps holding for HTML panes, so anchor survival, one-element-per-anchored-row, the engine's `offsetTop` math, and the R0003-0076 offsetParent probe all carry over with zero amendment; whole-document panes break the direct-child invariant and let source-controlled `style` attributes on preserved wrappers corrupt geometry. (3) D6's "script/style/head do not survive the mount" becomes true **by construction** — those bytes are gap or head content and never enter the pane files; DOMPurify stays as the fail-closed backstop, its config untouched. (4) It shrinks OI-0035's surface: gap markup is exactly where impostor anchors would ride.

**Derivation** — one function serving both panes (source over `doc.source_text`, target over the regenerated HTML), per row with `sync_role != "non-sync"`, in source order:

1. Slice the block's bytes via the row's byte range (`PaneCtx::new`'s `DuplicateRow` / `UncoveredBlock` / `UnusableRange` refusals carry over verbatim). The target string first passes the same `parser::intake` NUL-normalization guard that `render_target` applies to `translated_md` (verified in its doc comment) — otherwise the pane path indexes a different string than the one `regen` produced offsets into.
2. **Strip the reserved attribute namespace** from all markup inside the block's bytes (`strip_reserved_sync_attrs`, below) — strip-then-inject is what makes "ours are the only ones" a construction, not a scan.
3. **Inject the four attributes into the block's own outermost element's open tag**, a byte splice at the attribute-insertion offset (just before the closing `>` or `/>`), using `TagToken::Open.span`. No wrapper `<div>` for tables/code here — the Markdown path's wrapper existed because comrak output could not carry attributes (ADR-0007/DCR-0001); an HTML block's own element can. Deliberate, documented divergence. The attribute *text* comes from the existing `render::attrs::write_attrs(&AlignmentBlock)` so the two formats' spelling and order cannot fork.
4. An element-less block (a bare-text run, or an unclosed-fragment block missing its open tag) is wrapped in a transparent `<div{attrs}>…</div>` — the shipped DCR-0016 wrapper precedent.
5. **Balance the block** (`balance_fragment`) so a malformed block cannot swallow the next block's anchor.
6. **Consecutive `li` blocks are wrapped in one shared `<ul>`/`<ol>` group**, exactly as `render_list_group` does on the Markdown pane today — under D9 this is mandatory, not cosmetic: a bare `<li>` as a direct `<main>` child gets relocated by DOMPurify and the anchor moves with it.
7. Gap bytes, `<head>`, doctype, comments, `<script>`/`<style>`: **not emitted**. A `fallback_source` block renders live (its bytes are source bytes — already valid HTML) with `data-fallback="fallback_source"`; only an **extraction-failure** block takes the escaped `<pre data-skipped="html-block">` placeholder, mirroring DCR-0016's failure presentation.

The published **`out.html` is `regen::regenerate` output** — the full page, head, scripts, styles, doctype, anchor-free — exactly the relationship `out.md` has to the bundle today. Anchors never touch the regen path; injection is a bundle-only derivation. How identity survives: the same `block_id` flows IR → LLM → regenerated HTML → alignment row → this injection (which reads the *row*, not the document) → DOM anchor → engine. The document never gets to vote on its own anchors — half of OI-0035's fix falling out of the design.

**OI-0035, route (c) — both layers:**

- **Render half.** `transync_html::strip_reserved_sync_attrs(html) -> Cow<str>` removes, case-insensitively, the six reserved attribute names — `data-sync-id`, `data-block-kind`, `data-order`, `data-fallback`, `data-parent-id`, `data-skipped` — from element open tags. Two call sites: the Markdown path's `BlockKind::Html` success arm (the only live route by which source-controlled markup reaches a Markdown pane, since panes render with `render.unsafe_ = false` — verified), and the HTML pane derivation before injection. Strip is **pane-only**: `out.md` / `out.html` keep the author's bytes — their `data-sync-id` is their content; we own the namespace only in DOM we mount. Stripping never changes rendered appearance (attributes don't paint).
- **Engine half.** `mountSync` builds `rowIdSet` from validated rows with `sync_role !== "non-sync"` (the exact predicate `synchronizableRowCount` uses, so the two cannot disagree); `collectAnchors` — verified as the single choke point for both panes at mount *and* at every reflow recompute — takes the set and skips any element whose `data-sync-id` is not in it, warning at mount with the existing first-five-plus-tally policy, quiet on reflow. An unlisted anchor is **inert forever**, including one inserted after mount — closing the 2026-08-09 correction's residual. First-occurrence-wins within listed ids is unchanged. Both `sync.js` copies move in one commit; `sync_js_drift.rs` is the weld.
- **Honest residual, stated in the closure DCR:** the engine alone cannot defeat an in-pane impostor carrying a **listed** id that precedes the genuine anchor in document order — no DOM-visible discriminator exists. That is exactly why route (c) is both layers: the render strip guarantees *our* panes never contain one; the engine gate covers third-party producers and unlisted ids. Defense in depth, each layer covering the other's blind spot.
- **The `<title>` row needs zero engine changes** (verified interactions): `warnMapDomDrift` skips `non-sync` rows — no spurious drift warning; `synchronizableRowCount` excludes it — a title-only map still trips the empty-map gate when panes carry anchors and mounts over empty panes; `rowIdSet` excludes it — an element impersonating the title's id is inert for free. The "translated but not page content" status D5 needed already had a wire spelling shipped since schema 1.0.

## 13. Accepted limitations

Each of these is a knowing trade, recorded so the next reader does not mistake it for an oversight:

1. **Attribute text is untranslated** (D5): `alt`, `title`, `placeholder`, `<meta description>`, `og:*` stay source-language. Visible consequence, named in ADR-0025: a shared link previews in the source language. A future policy may revisit; nothing in this design forecloses it.
2. **Entity-spelling drift in translated segments** (D7): genuinely translated text loses named/numeric entity forms; untouched and identity-skipped segments keep source bytes exactly. Already test-pinned since DCR-0016.
3. **Panes are not a fidelity preview** (D6): no page layout, no styles, no scripts in the sync surface. The real page is `transync serve` over `out.html`.
4. **List markup is gap; one anchor per item** (D9): `<ul>`/`<ol>` tags never translate (they contain no text) and carry no anchor of their own; the items do.
5. **A custom element mid-sentence splits the sentence** (the PHRASING widening's consequence, §4) — accepted **for now**; see §14.
6. **The `<title>` has no anchor** (D5) — translated, aligned, honest `non-sync` row, no pane presence.
7. **The layer-6 twin's blind spots** (§7): swapped same-skeleton texts pass (parity with `reparse_full`); attribute values are untokenized (compensated); the scanner is one self-consistent opinion, not a general parser.
8. **OI-0035's in-pane-impostor residual** (§8): a listed id preceding the genuine anchor defeats the engine layer alone; the render strip is the layer that closes it for panes we produce.
9. **Markdown islands stay `BlockKind::Html`** (D11) until a schema-2.x window — the honest cost of the corpus-stability acceptance criterion.
10. **Foreign-content breakout tags and HTML integration points are not modelled by the walk** *(added 2026-08-24; **open, not accepted** — ti `e77173`)*. `<div class="wrap"><svg><div>x</svg></div>` followed by a block mounts that block's anchor inside the wrapper rather than as a direct child of `<main>`, breaking §4a — measured through the shipped DOMPurify mount, live today on the Markdown pane path, and reachable from untrusted source Markdown through a type-6 html block. The self-closing slash is **not** the mechanism: the unflagged `<svg><div>x</svg>` does the same thing, because `div` is on HTML's breakout list. Listed here so it is not mistaken for an oversight, but unlike items 1–9 it is **scheduled for fix, not accepted** — between wave 2 closing and wave 3 starting, because wave 3 consumes the same walk through `element_extents` and would bless an identity corpus over block boundaries a browser disagrees with. `docs/backlog.md` carries the disposition.

## 14. Post-implementation review items

1. **The PHRASING widening's consequence — owner-mandated re-confirmation.** `Price: <my-price/> today` splits into three blocks because a custom element mid-sentence stops (D4's default). This was accepted *for now*, and **the owner explicitly asked that it be re-confirmed after implementation, against real output** — real pages with web components, icon elements, and framework custom elements run through the intake, with the resulting block sets and translations reviewed. It is carried here as a named review item, not a settled matter. If real output shows unacceptable sentence-splitting, the candidate lever is a per-run or per-profile phrasing-extension list — designed then, not now.

## 15. Open questions

Genuinely unresolved items, each deliberately left to implementation time rather than guessed at here:

1. **The HTML pane derivation's module home and entry-point name** in `transync-syntax::render` — the render area marked its naming *inferred*; the final module shape is the implementing wave's, under the constraint that it stays inside `transync-syntax`/`transync-html` so the wasm gate's dependency rules hold.
2. **`ElementExtent`'s exact field shape** — §5's struct is the agreed seam (extents + tokens, one walker, classification stays in the intake); the fields are refined jointly when wave 3's consumer exists. The commitment that cannot move: the walk lives in `transync-html`, next to the balancer, and there is exactly one of it.
3. **DOMPurify's default keeping `data-*` attributes** was *inferred* from its documented `ALLOW_DATA_ATTR` default (consistent with OI-0035's own statement), not re-verified in the design session — verify during wave 1 before writing the closure DCR's mechanism sentence.
4. **Oversize leaf blocks** (a giant `<table>` or custom element exceeding the token budget): the design commits only to the *shape* — a packing-time segment-window split in the DCR-0026 mold, never intake descent (D4 rejected budget-driven block sets) — and to the wave-2 guard that excludes `(Table × Html)` from the GFM row-window splitter. The HTML segment-window splitter itself is future work, unscheduled; D9 removed its most common trigger (long lists).
5. **A mechanics watch item, flagged not blocking:** if regen ever needs splice over *merged multi-element ranges*, `BlankLinePolicy::Keep` still holds and extract/splice are slice-agnostic (**MEASURED** in the 2026-08-20 research pass: identity-splicing a whole `<!DOCTYPE html>` page returned output byte-identical to its input — `IDENTITY SPLICE BYTE-EQUAL: true` — over a probe crate built against `transync-syntax`; the same pass measured a 5.8 MB / 200,000-element document extracting cleanly, which is what retires the 4 MiB cap as a supposed document ceiling), but the layer-3 inventory check must then run over the same merged slice, not per element.
6. **The shipped `[system].prompt_html` body text** — authored at wave 5, with the same data-not-instructions posture as the Markdown prompt (invariant 7); this spec fixes the mechanism (sibling key, selection, load warning), not the prose.
