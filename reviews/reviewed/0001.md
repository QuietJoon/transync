## Critical

### R0001-0001 — Temp-root values pass destructive `rm -rf` guards

- Issue ID: R0001-0001
- Location: `scripts/smoke-live.sh:89`, `scripts/smoke.sh:32`, `scripts/test-browser.sh:35`
- Impact: Setting a work-directory variable to `/tmp/`, `/private/tmp/`, or another allow-listed root with a trailing slash passes `/tmp/*`-style shell patterns because `*` may match an empty suffix. The following `rm -rf "$WORKDIR"` can erase the entire temporary root and unrelated users' data.
- Evidence/reasoning: Each script checks a prefix glob, then recursively removes the value. None rejects equality with the root before the glob check.
- Recommendation: Canonicalize the candidate, explicitly reject every allow-listed root itself, require at least one descendant component, and centralize the guard in one shared helper.
- Ignore/Decision reference: None.

## High

### R0001-0002 — Destructive guards trust an arbitrary `transync-*` basename anywhere

- Issue ID: R0001-0002
- Location: `scripts/smoke-live.sh:105`, `scripts/smoke.sh:47`, `scripts/test-browser.sh:53`
- Impact: Any directory anywhere on disk is recursively deleted when its basename starts with `transync-`, including a real project or archive outside a temporary root.
- Evidence/reasoning: The fallback allow-list checks only `basename`, not the canonical parent or ownership. The scripts then run `rm -rf` without confirmation.
- Recommendation: Remove the basename-only escape hatch; require a canonical descendant of a configured temporary root and a script-owned marker file before deletion.
- Ignore/Decision reference: None.

### R0001-0003 — The default profile forces Korean glossary terms for every target language

- Issue ID: R0001-0003
- Location: `crates/transync-core/profiles/default.toml:27`, `crates/transync-cli/profiles/default.toml:25`
- Impact: A default translation to Japanese, French, or any other target is instructed to render `agent` and `tool use` in Korean, producing mixed-language output without any user opt-in.
- Evidence/reasoning: Both default profiles contain global Korean targets; `render_prompt_body` appends them unconditionally and performs no target-language filter.
- Recommendation: Ship an empty neutral default glossary, or make examples commented-only/sample-profile content.
- Ignore/Decision reference: ADR-0014 governs scope behavior but does not authorize target-language-specific entries in the universal default.

### R0001-0004 — Cache identity omits the enforced provider output ceiling

- Issue ID: R0001-0004
- Location: `crates/transync-core/src/cache.rs:21`, `crates/transync-core/src/pipeline.rs:789`, `crates/transync-openai/src/client.rs:200`
- Impact: Runs with different `target_output_tokens` can reuse the same cached unit although the original request had a different truncation/completion budget and could yield different content.
- Evidence/reasoning: `CacheKey` and `CacheKeyContext` contain no batching/output-ceiling field, while the OpenAI adapter sends it as `max_completion_tokens` or `max_output_tokens`.
- Recommendation: Add the effective output ceiling to cache identity, or include all output-affecting `ProfileBatching` fields in a canonical profile hash.
- Ignore/Decision reference: ADR-0015 requires cache hits to remain valid; it does not exempt request parameters that alter provider output.

### R0001-0005 — Cache identity omits co-batched peers

- Issue ID: R0001-0005
- Location: `crates/transync-core/src/pipeline.rs:825`, `crates/transync-openai/src/client.rs:640`
- Impact: The same unit can reuse output generated while surrounded by a different set of units, even though the provider receives the whole batch in one prompt and model output may be influenced by those peers.
- Evidence/reasoning: Keys are per-unit and contain no batch composition hash; `build_user_prompt` serializes every unit into the same user message.
- Recommendation: Hash the ordered batch cohort into each provisional cache key, or dispatch/cache units independently if peer independence is a required invariant.
- Ignore/Decision reference: None.

### R0001-0006 — Programmatic profiles bypass the rejected section-glossary invariant

- Issue ID: R0001-0006
- Location: `crates/transync-core/src/profile.rs:27`, `crates/transync-core/src/profile.rs:133`, `crates/transync-core/src/profile.rs:415`
- Impact: Library callers can construct or deserialize `ProfileMetadata` with `ConditionalOnSection`; translation then applies the entry globally, exactly the misleading behavior the TOML loader rejects.
- Evidence/reasoning: The invariant exists only in `load_profile`; public fields and derived `Deserialize` bypass it, and `format_glossary` never checks scope.
- Recommendation: Validate profiles at the `translate` boundary and make construction go through a checked constructor; reject unsupported scopes regardless of origin.
- Ignore/Decision reference: ADR-0014 explicitly rejects global treatment of section-scoped entries.

### R0001-0007 — Rejected provider attempts can determine the reported source language

- Issue ID: R0001-0007

- Evidence/reasoning: `detected_source_language` is captured before `validate_batch` and only while `None`; later retry values cannot replace it.
- Recommendation: Commit language detection only from an attempt that passes the batch schema and define whether per-kind rejection is sufficient to disqualify it.
- Ignore/Decision reference: None.

### R0001-0008 — Deep blockquote structure can change without rejection

- Issue ID: R0001-0008
- Location: `crates/transync-core/src/unit.rs:285`, `crates/transync-core/src/validate/per_kind.rs:147`
- Impact: A provider can add, remove, or reshape structure more than one level below a blockquote while all validators and the top-level reparse pass.
- Evidence/reasoning: `blockquote_child_label` explicitly caps recursion at one level; the full reparse checks only top-level kind/count.

- Ignore/Decision reference: No ADR accepts silent deep-structure drift; README claims blockquote nesting is preserved.

### R0001-0009 — Inline raw HTML bypasses the stated raw-HTML rejection invariant

- Issue ID: R0001-0009
- Location: `crates/transync-core/src/validate/fragment_reparse.rs:24`, `crates/transync-core/src/parser.rs:88`
- Impact: Translated Markdown can contain newly introduced inline HTML even though validator comments state raw HTML is disabled/escaped/rejected. HTML rendering escapes it, but the emitted Markdown still carries provider-inserted markup.

- Ignore/Decision reference: None.

### R0001-0011 — Cache-revalidation retries are counted inconsistently

- Issue ID: R0001-0011
- Location: `crates/transync-core/src/pipeline.rs:731`, `crates/transync-core/src/pipeline.rs:231`
- Impact: A rejected cache hit followed by one successful network attempt produces `total_retries = 1` but `validation_summary.retried_units = 0`, so two published diagnostics disagree.

### R0001-0012 — Validation retry hints are never re-budgeted

- Issue ID: R0001-0012
- Location: `crates/transync-core/src/batch.rs:44`, `crates/transync-core/src/pipeline.rs:445`, `crates/transync-core/src/pipeline/retry.rs:12`

### R0001-0013 — Token budgeting materially undercounts provider-visible input
