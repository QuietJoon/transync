# 실행 간 웜 캐시를 재사용하는 방법

이미 제공자에게 문서 번역 비용을 지불했습니다. 편집 후, 실행 실패 후, 또는 출력 상한을 높이고 재시도한 후 해당 문서에 대한 다음 실행 비용이 실제로 변경된 부분에 대해서만 발생하기를 원할 때 이 방법을 사용하세요.

## 사전 요구 사항

- 이미 엔드투엔드로 작동하는 `transync translate` 호출. 아직 없다면 [CLI로 Markdown 문서 번역하는 방법](./translate-a-document-with-the-cli.md)부터 시작하세요.
- 캐시전용으로 지정할 수 있는 디렉터리. 아직 존재할 필요는 없으며, 실행이 사용 중인 동안에는 다른 어떤 프로세스도 해당 디렉터리에 쓸 수 없습니다 (단계 5 참조).
- 기타 항목 없음. 서비스, 환경 변수, 프로필 설정이 필요하지 않습니다.

## 1. 첫 번째 실행에 `--cache-dir` 추가

```bash
transync translate \
  --input README.md \
  --out-dir dist/out \
  --target-language ko \
  --cache-dir .transync-cache
```

`--cache-dir`는 디렉터리 경로 하나를 받으며, transync가 처음 열 때 존재하지 않는 상위 디렉터리와 함께 생성합니다. 이 플래그는 기본값, 환경 변수 폴백, 프로필 상응 항목이 없습니다: 캐시가 위치하는 장소는 호출별 결정이므로 이 플래그가 전적인 제어 장치입니다. 이 플래그가 없으면 각 실행은 일회성 메모리 내 캐시를 구축하고 종료 시 삭제하므로, 캐시되지 않은 재실행에는 전체 비용이 발생합니다.

이후 디렉터리는 `transync-cache.jsonl`이라는 단일 파일을 보관합니다 — 줄당 하나의 JSON 객체로 구성된 추가 전용 로그로, 이후 실행이 열 때 메모리로 재생됩니다. 수락된 모든 유닛은 수락되는 즉시 추가되고 플러시되므로 Ctrl-C로 중단한 실행이라도 이미 검증(Validation)을 마친 모든 항목을 남겨둡니다.

인자 테이블의 플래그 항목은 [CLI 플래그](../../../reference/user/en/cli.md)에 위치하며, 이 페이지는 목록이 아닌 레시피 가이드입니다.

## 2. 동일한 디렉터리에 대해 다시 실행

문서를 편집하거나(또는 아무것도 변경하지 않고) `--cache-dir`을 포함하여 동일한 명령을 다시 실행합니다:

```bash
transync translate \
  --input README.md \
  --out-dir dist/out \
  --target-language ko \
  --cache-dir .transync-cache
```

정체성이 변경되지 않은 유닛은 로그에서 제공되며 제공자에 도달하지 않습니다. 나머지 부분만 디스패치됩니다. 출력 세트에 대한 어떠한 것도 변경되지 않습니다: 번역된 Markdown, 정렬 맵, 검증 보고서 및 데모 번들은 콜드 실행에서와 정확히 동일하게 쓰여집니다.

웜 디렉터리가 전달하는 다른 두 가지 사항으로, 웜 실행이 이전에 지불했던 제공자 호출을 제거하므로 알아둘 가치가 있습니다:

- **감지된 소스 언어.** `--source-language auto` 실행은 문서에 대해 제공자가 보고한 내용을 저장하므로, 완전히 캐시 히트된 재실행에서도 아무것도 보고하지 않는 대신 정렬 맵과 데모 번들의 `lang` 속성에 언어를 계속 보고할 수 있습니다.
- **자동 용어집 수확물**, `--auto-glossary`로 실행하는 경우. 호출이 이루어지기 전에 사전 점검이 캐시에서 조회되므로, 두 번째 실행은 새롭고 아마도 다른 수확물을 구입하는 대신 첫 번째 실행의 수확물을 재생합니다.

## 3. 항목을 무효화하는 요인 파악

항목은 해당 한 블록에 대해 모델이 본 프롬프트 바이트에 도달한 모든 요소와 응답한 주체 및 계약에 의해 식별됩니다. 이 중 어느 것이든 변경되면 해당 유닛이 다시 디스패치됩니다.

| 변경하는 항목 | 캐시에 미치는 영향 |
|---|---|
| 블록 자체의 원문 텍스트 | 해당 유닛이 미스되며, 이웃 유닛도 미스되는 경우가 많음 — 아래의 폭발 반경 노트를 참조하세요. |
| 헤딩, 또는 섹션 트리에서 블록의 위치 | 섹션 경로나 헤딩 레벨이 이동한 모든 유닛이 미스됩니다. |
| 프로필 — 버전 문자열, 프롬프트 본문 또는 용어집 (Glossary) | 프로필 아래의 모든 유닛이 미스됩니다. |
| `--model` (또는 `TRANSYNC_OPENAI_MODEL`) | 모든 것이 미스됩니다. |
| 제공자 정체성: `--base-url`, 해석된 API 표면, 추론 노력 (reasoning effort) | 모든 것이 미스됩니다. |
| `--source-language` 또는 `--target-language` 레이블 | 모든 것이 미스됩니다. 레이블은 작성된 대로 비교되므로 `ko`와 `Korean`은 서로 다른 두 개의 네임스페이스입니다. |
| 검증 스키마 상향 버전에 맞춰 transync 업그레이드 | 모든 것이 미스됩니다. |

그리고 모델이 읽은 바이트가 없기 때문에 재디스패치 비용이 들지 **않는** 변경 사항:

| 변경하는 항목 | 캐시에 미치는 영향 |
|---|---|
| `--target-output-tokens` (중단 후 이를 올리는 경우 포함) | 아무것도 무효화되지 않음. |
| `--max-concurrent-batches` | 아무것도 무효화되지 않음. |
| 출력 경로 — `--out-dir`, `--output`, `--map`, `--html-out`, `--validation-report` | 아무것도 무효화되지 않음. |
| `--quiet` / `--verbose` / `--force` | 아무것도 무효화되지 않음. |

`--max-units-per-batch`는 둘 사이에 위치합니다. 패킹 예산 자체는 항목 정체성의 일부가 아니지만 배치가 조립하는 지시사항은 정체성의 일부이며, 재패킹을 통해 원시 HTML 유닛이나 크기 초과 테이블 행 윈도우를 포함하는 배치 내부로 유닛이 이동하거나 외부로 벗어날 수 있습니다 — 이것이 배치 작업 조절기가 지시사항 및 키를 변경하는 한 가지 방법입니다.

**단일 유닛이 아닌 편집 주변의 폭발 반경을 예상하세요.** 유닛의 정체성에는 모델이 함께 본 컨텍스트 힌트(문서 제목, 섹션 경로 및 헤딩 레벨, 이웃의 종류 및 요약)가 포함됩니다. 따라서 한 단락을 편집하면 이웃 단락에서도 미스가 발생할 수 있으며, 헤딩을 편집하면 하위 유닛에서도 미스가 발생할 수 있습니다. 이는 낭비라기보다 올바른 동작입니다: 다른 헤딩 경로에서 생성된 번역은 다른 질문에 대해 생성된 것이기 때문입니다.

## 4. 재사용 확인

`--validation-report report.json`을 전달하거나(`--out-dir`이 항상 작성하는 사본을 읽고) `per_unit[*].attempts`를 확인하세요. 캐시에서 제공되는 유닛은 `attempt_number: 0`으로 기록됩니다 — 캐시 히트는 네트워크 시도가 아니므로 완전히 웜 상태인 실행에서는 `0`을 초과하는 시도가 전혀 표시되지 않습니다.

캐시된 유닛이 맹목적으로 신뢰되지는 않습니다: 모든 히트는 라이브 응답이 거치는 것과 동일한 유닛별 레이어를 통해 재검증되며, 실패한 히트는 축출되고 다시 디스패치됩니다. 따라서 손상되거나 오래된 캐시로 인해 재번역 비용이 발생할 수는 있지만 잘못된 문서가 생성되지는 않습니다.

캐시 실패가 아닌 한 가지 결과: **부분적인 웜 재실행 후 감지된 언어가 비어 있음**. 저장된 감지는 제공자 배치를 0개 디스패치한 실행에 의해서만 재생됩니다. 한 번이라도 제공자 호출을 수행한 실행은 제공자가 말한 내용(침묵 포함)을 보고하며 스토어를 조회하지 않습니다. 재생은 캐시가 생략한 호출을 보상하기 위해 존재하는 것이지 라이브 답변을 오버라이드하기 위해 존재하는 것이 아니기 때문입니다. 보고서의 나머지 부분도 잘못된 것처럼 보이면 [번역 실행 진단하는 방법](./diagnose-a-translation-run.md)을 참조하세요.

## 5. 디렉터리 운영

**한 번에 하나의 작성자만 허용.** 하나의 캐시 디렉터리를 두 실행이 동시에 공유하는 것은 지원되지 않습니다: 락 파일이 없으며 계획되어 있지 않습니다. 사람당 하나의 디렉터리를 사용하고 공유 네트워크 드라이브가 아닌 로컬 디스크에 보관하세요. 이 규칙을 위반했을 때의 비용은 제한적입니다 — 리더는 인터리브되거나 찢어진 줄을 삭제하고, 압축 레이스는 다른 프로세스의 최근 추가 항목을 잃게 되므로 손실되는 것은 항목(재번역을 의미)이며 결코 출력 손상이나 실행 실패가 아닙니다.

**로그에는 오픈 시 확인되는 상한선이 있습니다.** 기본 예산은 1 GiB이며, 현재 파일 크기가 아닌 압축된 로그가 차지할 크기로 측정됩니다. 이는 오픈 시에만 적용되고 실행 중에는 적용되지 않으므로 단일 실행이 초과할 수 있으며 다음 실행이 정리(trim)합니다. 정리는 **가장 오래 전에 작성된** 라이브 항목부터 삭제합니다 — 이는 의도적으로 LRU(가장 최근에 사용되지 않음) 방식이 아닙니다. 읽기 최신성을 영속화하면 모든 조회가 디스크 쓰기로 바뀌기 때문입니다. 정리는 `transync::cache` 타깃의 `WARN` 레코드로 알림이 표시되며, 기본 상세도에서 stderr에 도달하고 `--quiet`에 의해 무음 처리됩니다:

```
cache log .transync-cache/transync-cache.jsonl exceeded its budget; dropped 12 oldest-written entr(ies), 400 kept
```

**세 가지 파일 이름이 나타날 수 있으며, 하나만 다시 읽힙니다.**

| 파일 | 설명 |
|---|---|
| `transync-cache.jsonl` | 라이브 로그. 실행이 읽는 유일한 파일. |
| `transync-cache.jsonl.unreadable-<unix-seconds>` | 헤더가 누락되었거나 알 수 없는 형식의 로그. 삭제되지 않고 치워지며, 캐시는 비어 있는 상태로 시작합니다. 더 이상 증거를 원하지 않으면 안심하고 삭제할 수 있습니다. |
| `transync-cache.jsonl.compact-<pid>-<nanos>` | 이름 변경 전 크래시로 인해 남겨진 압축 임시 파일. 비활성 상태이며 절대 읽히지 않고 transync에 의해 정리되지도 않습니다. 안심하고 삭제할 수 있습니다. |

아무것도 마지막 두 항목을 회수하지 않으므로, 캐시 디렉터리는 예산이 설명하는 것보다 더 많은 바이트를 보관할 수 있습니다; 삭제는 사용자가 직접 수행해야 합니다.

**열 수 없는 디렉터리는 성능 저하될 뿐 실패하지 않습니다.** 경로를 열 수 없는 경우(기존 일반 파일임, 상위 디렉터리가 읽기 전용임, 볼륨이 사라짐) 실행 시 한 번 알리고 새로운 메모리 내 캐시로 계속 진행합니다:

```
transync: could not open --cache-dir <path>: <error>; continuing with a fresh in-memory cache (this run will not reuse or persist anything)
```

이는 경고이며 실패가 아닙니다: 종료 코드에는 영향이 없으며 번역은 전체 비용으로 진행됩니다. `--quiet`은 해당 줄을 억제하므로 캐싱 작동 여부를 확인하는 실행에서는 `--quiet`을 사용하지 마세요.

**디렉터리를 삭제하는 것은 언제나 안전합니다.** 다음 실행 시 처음부터 다시 번역하고 디렉터리를 재구축합니다.

## 알아두어야 할 제한 사항

- **용량 정책은 CLI에서 접근할 수 없습니다.** 모든 CLI 실행은 기본 1 GiB 바이트 예산을 받으며 항목 상한은 없습니다. 이를 변경할 플래그, 환경 변수, 프로필 테이블이 없습니다; 바이트 및 항목 예산은 라이브러리 전용 설정으로, 캐시 자체를 구축하는 코드에서 사용 가능합니다.
- **압축 중 크래시가 발생하면 임시 파일이 남습니다.** 아무것도 이를 제거하지 않습니다. 위의 파일 테이블을 참조하세요.
- **쓰기는 플러시되지만 `fsync`되지는 않습니다.** 레코드는 Ctrl-C를 포함한 프로세스 종료 시에도 유지됩니다. 운영체제 크래시로 인해 로그의 꼬리 부분이 손실될 수 있습니다 — 다음 열기 시 이를 찢어진 레코드로 폐기하여 손상이 아닌 재번역으로 처리합니다.
- **캐시 디렉터리는 동일한 transync 빌드를 실행하는 머신 간에 이식 가능합니다**, 키의 어떤 것도 머신이나 실행 시드(salt)를 포함하지 않기 때문입니다. 이는 하나의 속성일 뿐, 두 개의 동시 실행 간에 하나의 디렉터리를 공유하라는 초대장이 아닙니다.
