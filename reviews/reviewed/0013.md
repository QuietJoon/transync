## Findings

### 1. A final output can consume another output's staged bytes

**[HIGH] Fileset destination validation omits final-to-temporary path collisions**

**Issue ID:** R0013-0001

**Location:** `crates/transync-cli/src/output/fileset.rs:44`, `crates/transync-cli/src/output/fileset.rs:241`, `crates/transync-cli/src/output/fileset.rs:288`; `crates/transync-cli/src/output/destination.rs:43`.

**Impact:** A successful publication can lose one requested output and put the wrong content into another. No concurrent writer, symlink attack, or interrupted rename is needed.

**Evidence / reasoning:** Let the process ID be `P`, and supply, in order, final destinations `out.json.tmp.P` and `out.json`, initially absent. The final names are distinct, so `vet_destinations` accepts them. Staging produces `out.json.tmp.P.tmp.P` containing the first payload and `out.json.tmp.P` containing the second. The first commit renames its temp onto `out.json.tmp.P`, overwriting the second payload's temp. The second commit then moves those first-payload bytes to `out.json`. Both renames succeed on the supported Unix path, but the first destination disappears and the second has the wrong bytes. The CLI constructs its individual output/map destinations in that order, so this is reachable through normal arguments when the caller knows the child PID, for example through a shell `exec` wrapper. `create_new` does not protect against this: both staging paths were absent when opened.

**Recommendation:** Validate the complete reserved namespace—final destinations and every derived staging destination—before staging. Share the derivation with the writer and also use it at CLI preflight so deterministic refusal occurs before provider work.

**Ignore/Decision reference:** ADR-0024 accepts interruption and I/O failure windows, not deterministic wrong-byte publication that returns success. R0012-0005 concerns the lock-marker name and is a different collision. Existing final/final duplicate and containment checks do not cover this case.

**Patch coverage:** Proposed writer-side namespace validation and shared staging-name derivation. Moving the same check into the early CLI preflight remains follow-up work.

### 2. Small deeply nested HTML has quadratic intake cost

**[HIGH] Every open HTML container retains a complete copy of its ancestor path**

**Issue ID:** R0013-0002

**Location:** `crates/transync-syntax/src/intake/html.rs:178`, `crates/transync-syntax/src/intake/html.rs:604`, `crates/transync-syntax/src/intake/html.rs:620`; related CPU amplification at `crates/transync-html/src/lib.rs:1970` and `crates/transync-html/src/lib.rs:2197`.

**Impact:** A small source document can exhaust process or browser memory before translation. Removing the memory amplification still leaves a quadratic scanner path to address.

**Evidence / reasoning:** `Container.path` stores all ancestor ordinals. `enter_container` calls `next_child_path`, which clones the entire last container path and pushes another ordinal. All these vectors remain live until their containers close. For `N` nested `<div>` containers surrounding one paragraph, retained ordinal storage is `N(N+1)/2` words, even though there is only one emitted prose block. At 20,000 containers, an approximately 220 KB input retains roughly 1.6 GB of ordinal data on a 64-bit target, before allocation metadata and other structures. The later 4 MiB `lol_html` extraction ceiling does not govern these vectors. Separately, each `<div>` asks `in_scope` whether a `p` exists in button scope; a stack containing only `div` elements supplies neither a match nor a terminating boundary, so each start tag scans its ancestors again. These are two costs of the same deep-input failure, grouped here rather than counted separately.

**Recommendation:** Store one ordinal per open container and materialize the full path only for emitted blocks. Bound or remove repeated full-stack scope searches; decide an explicit HTML resource/depth policy if a limit is needed. Preserve the existing path convention and tolerant intake behavior.

**Ignore/Decision reference:** ADR-0016 accepts holding a document in memory; it does not justify retaining quadratic copies of intermediate ancestor state. OI-0040's repeat parses and OI-0049's naked-run/trim costs concern different inputs and algorithms.

**Patch coverage:** Proposed compact container state fixes the intermediate-path memory amplification. Scanner scope-search complexity is not fixed by that patch; the finding remains partly open.

### 3. Container-local definitions escape the URL-preservation check

**[MEDIUM] The reference-definition pool omits definitions inside blockquotes and list items**

**Issue ID:** R0013-0003

**Location:** `crates/transync-syntax/src/intake/markdown/refdefs.rs:45`; `crates/transync-core/src/validate/inline.rs:128`, `crates/transync-core/src/validate/inline.rs:273`; `crates/transync-core/src/validate/full_reparse.rs:106`.

**Impact:** A provider can remove a real reference link without violating the default URL-preservation gate. The resulting full document loses its destination even though the per-unit validator accepts it.

**Evidence / reasoning:** `refdefs::extract` examines only gaps between top-level blocks. It never examines definition lines inside a blockquote or list-item range. Those definitions have document-wide effect under CommonMark; the official specification demonstrates a definition inside a blockquote resolving a reference outside it. See [CommonMark 0.31.2, example 218](https://spec.commonmark.org/0.31.2/#example-218).

For example, retain the first block and change only the final paragraph:

```markdown
> [ref]: https://example.com/
>
> Definition holder.

Read [docs][ref].
```

The paragraph's source inventory is parsed alone with an empty pool, so `[docs][ref]` is plain bracket text and contributes no `NodeValue::Link`. A result of `Read docs.` also contributes no link. Both contain visible text and are paragraphs. Full-document validation compares top-level kinds/counts and list-item counts, not link destinations, so it does not recover this lost invariant. This is a validation defect; current whole-document pane rendering is not being accused of using the old fragment pool.

**Recommendation:** Obtain effective definitions or resolved source-link inventories from the original whole-document parse, including container definitions and first-definition-wins ordering. Feed that information into translated-fragment validation. Include nested definitions and duplicate-label precedence in the regression cases; stripping `>` or list prefixes with a line regex would not respect code fences or CommonMark container grammar.

**Ignore/Decision reference:** ADR-0012's reference-link amendment intends to close reference-style URL protection. OI-0040 concerns pooling/parse cost, not definitions absent from the pool. No accepted exception for container definitions was found.

**Patch coverage:** No hunk proposed: the appropriate fix requires choosing how the intake retains parser-derived reference state across the existing `Document`/validator boundary. A speculative text-prefix extractor would be an unsafe replacement for the parser's answer.

### 4. The visible-text layer admits an omitted invisible control family

**[MEDIUM] Shorthand format controls satisfy `has_visible_text`**

**Issue ID:** R0013-0004

**Location:** `crates/transync-core/src/validate/text_presence.rs:89`, `crates/transync-core/src/validate/text_presence.rs:117`.

**Impact:** A nonempty translated payload consisting entirely of default-ignorable shorthand controls can pass the layer intended to reject invisible replacement text.

**Evidence / reasoning:** `is_invisible` explicitly enumerates invisible ranges, but omits U+1BCA0–U+1BCA3. These are assigned `Cf` shorthand-format characters with the `Default_Ignorable_Code_Point` property in the [Unicode Derived Core Properties data](https://www.unicode.org/Public/UCD/latest/ucd/DerivedCoreProperties.txt). They are not whitespace. Therefore a string containing only U+1BCA0 makes `has_visible_text` return true. For an ordinary paragraph without protected links/code, replacing its words with that string still gives a paragraph, an empty inline inventory on both sides, and a successful visible-text check. The acceptance is established from code; no claim about a particular installed browser/font was measured.

**Recommendation:** Include this assigned control range. Maintain the predicate against a stated Unicode property/version, while retaining any deliberate additions such as braille blank, so future hand-maintained omissions are reviewable.

**Ignore/Decision reference:** DCR-0048 adds an always-on guard against zero-width-only replacement. No accepted exception for shorthand format controls was found.

**Patch coverage:** Adds the missing assigned range. It does not claim the entire manually maintained predicate is now an exhaustive Unicode conformance implementation.

### 5. Invalid cache hits reverse the first request's unit order

**[MEDIUM] Requeued cache hits are appended after all cache misses**

**Issue ID:** R0013-0005

**Location:** `crates/transync-core/src/pipeline/dispatch.rs:214`, `crates/transync-core/src/pipeline/dispatch.rs:295`, `crates/transync-core/src/pipeline/dispatch.rs:348`.

**Impact:** A partially populated cache changes the document order presented in a provider request. A heading or earlier paragraph rejected from cache can appear after its later prose, undermining the section-coherent ordering that batching otherwise preserves. Final output order may still be correct because results are keyed by ID.

**Evidence / reasoning:** For original units `[A, B]`, let `A` have a cache hit that fails validation and let `B` miss. The lookup loop first creates `pending_units = [B]`. The synthetic cache-validation loop then evicts `A` and pushes its original unit, producing `[B, A]`. `current_batches` takes that vector unchanged for the first dispatch. This is an actual request-order change, not nondeterminism inferred from a hash map. It also occurs for interleaved stale hits and misses in larger batches.

**Recommendation:** Restore pending units to their original batch positions after validating cache hits and before constructing the first request. Do not sort textual IDs: numeric ordinals and row-window suffixes make that a separate ordering convention.

**Ignore/Decision reference:** ADR-0015 requires invalid-hit eviction and redispatch, which should be retained. DCR-0027's partition contract preserves document order; this finding concerns dispatch after partitioning, not the accepted coalescing behavior of DCR-0057.

**Patch coverage:** Sorts pending units by a map of their original batch positions.

### 6. Legal destination names become illegal staging names

**[LOW] Staging suffixes exceed filesystem component limits for otherwise valid paths**

**Issue ID:** R0013-0006

**Location:** `crates/transync-cli/src/output/fileset.rs:241`; `crates/transync-cli/src/output/publish.rs:578`; `crates/transync-cli/src/output/destination.rs:92`.

**Impact:** An otherwise writable destination can fail only at publication, after translation work, because the implementation requires a longer sibling name than the filesystem supports.

**Evidence / reasoning:** Plain files append `.tmp.<pid>` to the entire final component. Directory publication uses `.<name>.staging.<pid>.<token>` and a similar backup name. On a filesystem allowing 255-byte components, a legal 255-byte ASCII destination necessarily creates an over-limit staging component; many shorter out-dir names also exceed the limit after the larger suffix. `destination_file_name` checks presence and UTF-8 only. Final/final identity checks cannot detect this expansion problem. This finding is conditional on the filesystem's component limit and does not assume that every platform has the same limit.

**Recommendation:** Use bounded sibling names whose lengths do not grow with the destination component, with an ownership/collision scheme compatible with cleanup. At minimum, expose any intentional narrower naming limit during preflight before provider work rather than letting staging discover it.

**Ignore/Decision reference:** ADR-0024 specifies staging ownership and cleanup; it does not record a destination-name length restriction. OI-0049's invalid-parent preflight residual is separate from a valid final component becoming an invalid derived name.

**Patch coverage:** No hunk proposed: changing sibling naming also changes the recorded reclaim/backup ownership protocol. Choose that scheme, or an explicit preflight naming restriction, before changing one call site alone.

### 7. Synthetic cache validation clones units it immediately discards

**[LOW] Struct-update syntax clones the entire original batch unnecessarily**

**Issue ID:** R0013-0007

**Location:** `crates/transync-core/src/pipeline/dispatch.rs:251`.

**Impact:** Cache-hit processing performs an avoidable deep clone of every original unit, including payloads and contexts, in addition to cloning the selected cached units. The cost is most relevant when a warm cache avoids network latency.

**Evidence / reasoning:** The initializer explicitly supplies `batch_id` and a filtered/cloned `units` vector, then uses `..batch.clone()`. Calling `clone()` on the full `TranslationBatch` clones its original units before the struct update discards that overridden field. Only the language labels, glossary, and profile are needed from the base value. This is a source-level allocation opportunity; optimized-code elimination or an elapsed-time gain was not measured.

**Recommendation:** Initialize the four remaining fields explicitly, preserving the selected unit vector without first cloning the entire batch.

**Ignore/Decision reference:** OI-0051 tracks profile/glossary replication across batches. This is a separate discarded unit/payload clone inside cache-hit validation; the proposed fix retains the necessary profile/glossary clones.

**Patch coverage:** Replaces the full-batch clone with explicit remaining fields.

### 8. Output-only estimation performs input-only serialization and tokenization

**[LOW] `estimate_unit_output_tokens` computes and discards the complete input estimate**

**Issue ID:** R0013-0008

**Location:** `crates/transync-core/src/batch.rs:494`, `crates/transync-core/src/batch.rs:598`, `crates/transync-core/src/batch.rs:644`.

**Impact:** Output-budget warning generation and other output-only callers serialize/tokenize context and advisory hints that cannot affect the returned number.

**Evidence / reasoning:** The public helper calls `estimate_unit(unit, ...).output`. That function encodes the source payload, ID, kind, context JSON, and advisory JSON to construct both estimates. The output field uses only payload tokens, ID tokens, and the expansion factor. The same file already has `estimate_payload_output_tokens`, which computes exactly those inputs and calls the same `output_estimate` arithmetic. `output_budget_warnings` invokes the heavier helper for each unit with a configured output ceiling. No benchmark was run; the finding is the unnecessary input-specific serialization/encoding.

**Recommendation:** Delegate the output-only helper to `estimate_payload_output_tokens` with the unit's payload and ID. Keep the combined estimator for packers that need both values.

**Ignore/Decision reference:** OI-0041's repeated table planning and profile/glossary work are different computations; this does not propose reopening those declined items or hoisting the encoder globally.

**Patch coverage:** Reuses the existing output-only estimator.

### 9. Raw-text scanning repeatedly allocates the same closing prefix

**[LOW] Every less-than byte in a raw-text region rebuilds its closing-tag probe**

**Issue ID:** R0013-0009

**Location:** `crates/transync-html/src/lib.rs:903`, `crates/transync-html/src/lib.rs:909`, `crates/transync-html/src/lib.rs:1365`.

**Impact:** A script/style or RCDATA region with many less-than characters performs one avoidable heap-string construction per candidate, despite its expected closing name remaining constant.

**Evidence / reasoning:** While `raw_until` is set, each candidate executes `format!("</{close_name}")`. A region containing repeated `a < b` therefore allocates the same prefix repeatedly. The prefix changes only when entering a different raw-text element. This is independent of the script double-escaped-state correctness issue already reported in 0012.

**Recommendation:** Construct the `</name` prefix once when entering raw-text state and borrow it for subsequent byte comparisons. Preserve the delimiter and case-insensitive comparison checks.

**Ignore/Decision reference:** DCR-0042/DCR-0050's content-mode and raw-text semantics remain unchanged. This is not a new report of R0012-0004.

**Patch coverage:** Stores the complete closing prefix in the existing raw-text state.

### 10. Cache documentation promises corruption detection the validators cannot provide

**[LOW] Structural revalidation is described as a guarantee against all payload corruption**

**Issue ID:** R0013-0010

**Location:** `crates/transync-core/src/cache/disk.rs:292`; `docs/decisions/0021-disk-cache-jsonl-log-and-document-metadata.md:124`.

**Impact:** Maintainers and operators are given a stronger cache-integrity guarantee than the implementation supplies, obscuring an accepted residual of the no-checksum design.

**Evidence / reasoning:** The source comment says a flipped payload bit necessarily produces retranslation rather than a corrupted document; ADR-0021's consequences similarly say damaged-but-parseable payloads are caught. Revalidation checks schema, structure, selected inline invariants, and visible-text presence, not semantic equality or a stored checksum of translated prose. A bit flip changing a translated paragraph's ASCII `100` to `900` leaves valid UTF-8, JSON, paragraph structure, and visible text, and can pass every relevant check. The example does not require modifying an identity key or bypassing cache lookup.

**Recommendation:** Narrow the documentation to malformed or invariant-breaking damage. Explicitly acknowledge that same-shape semantic corruption may survive. This finding does **not** request introducing checksums or reversing the accepted persistence design.

**Ignore/Decision reference:** ADR-0021's JSONL/no-checksum choice is respected. ADR-0015's hit revalidation supplies useful structural protection but cannot establish the stronger prose-integrity claim.

**Patch coverage:** Corrects the source comment and the living ADR's consequence statement without changing cache behavior or historical DCRs.

**Evidence / reasoning:** The syntax inventory names `parser::{intake, parse, comrak_options}` and `parser::refdefs`. `crates/transync-syntax/src/lib.rs` exports `intake`, not `parser`; the Markdown implementation is now `intake::markdown`. **Ignore/Decision reference:** DCR-0053 records the Markdown module move; keeping its generated inventory stale is not a new public-API design decision. This finding does not propose exporting the internal scanning functions.
